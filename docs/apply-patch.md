# 文件补丁工具

`apply_patch` 是默认基础工具。一次调用可以新增、修改、删除或移动多个 UTF-8 文本文件；多处关联修改优先使用它，简单精确替换仍可使用 `str_replace`。

参数只有 `patch` 字符串。补丁必须完整，不接受 Markdown 代码围栏或普通 unified diff 作为输入。

```text
*** Begin Patch
*** Update File: src/example.rs
@@
-old text
+new text
*** Add File: notes.txt
+new file
*** Update File: old-name.txt
*** Move to: new-name.txt
*** Delete File: obsolete.txt
*** End Patch
```

## 匹配与文件边界

- `@@` 后的行必须以空格、`-` 或 `+` 开头，分别表示上下文、删除和新增；空白上下文行也需要空格前缀。
- 上下文按行精确且唯一匹配，不忽略缩进或空白。多个片段按顺序匹配，不允许重叠。
- `@@ anchor` 从唯一匹配的 `anchor` 行之后查找；`*** End of File` 要求前一个片段位于文件末尾。
- 无旧上下文的插入必须有唯一锚点、明确的文件末尾标记，或面向空文件。
- 已有文件保留 BOM、纯 LF/CRLF 和末尾换行。`\ No newline at end of file` 标记其上一行不含末尾换行；混合行尾文件的内容修改应使用 `str_replace`。
- 新增文件不能覆盖现有文件，移动不能覆盖目标；同一补丁不能重复操作同一路径，也不能同时操作父路径及其子路径。
- 相对路径使用当前会话或子任务的工作目录；绝对路径仍受现有权限策略约束。拒绝 `..` 跳转、符号链接、硬链接、特殊文件、二进制和非 UTF-8 文件。
- 上限为 1 MiB 补丁、64 个文件操作、单文件 8 MiB 或 200000 行，以及新旧内容合计 32 MiB。

## 并发与失败

`apply_patch`、`write_file`、`str_replace` 使用按规范路径排序的共享进程间锁。锁覆盖完整读改写过程，等待总时限为十秒；不同文件可以并行处理。

补丁先验证全部文件，再在同目录暂存内容，并在提交前复查内容和元数据。父目录通过不跟随符号链接的句柄访问，原有文件权限随修改或移动保留。提交前取消不会写入目标文件；提交开始后会完成提交或执行失败恢复。

多个文件没有操作系统级整体事务。正常执行错误会尝试恢复已提交文件；进程崩溃、断电及不遵守锁协议的外部程序仍可能造成部分修改。恢复时发现外部编辑不会将其覆盖，而会返回 `ROLLBACK INCOMPLETE` 和涉及路径。出现部分失败后必须检查文件，不能盲目重试。

## 界面与权限

- 工具标记为写入操作：规划模式阻止执行，审计模式沿用审批与审计记录。
- 默认工程工具集包含该工具，非独占旧工程配置会随 `write_file` 补充它；独占白名单仍保持精确控制。
- TUI 和 Web 复用现有编辑图标、审批差异、流式增删统计及结果差异视图。
- 成功结果包含 `changed_files` 和 `diff`；移动结果额外包含 `source_path`。Web 只把执行报告中的文件加入本轮变更列表，不把失败或未完成的补丁参数当成实际修改。

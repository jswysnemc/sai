# Plan 模式

Plan 模式用于先调查、设计和审阅，再进入实施。使用 `/plan` 进入；Plan 是独立的只读工作模式，不再属于权限模式选择器。模型也可以调用 `enter_plan_mode`，此时记录进入前的执行模式。

## 流程

1. 只读探索代码和约束，重要分歧使用 `ask_question` 澄清。
2. 编写包含目标、范围、文件、步骤、验证方式与风险的完整 Markdown 计划。
3. 调用 `exit_plan_mode`，传入 `title` 和完整 `plan` 正文。
4. TUI 先打开可滚动、可搜索的 Markdown 预览；关闭预览后选择批准、继续规划或输入修改意见。Web 将完整正文放在审批选项上方。
5. 只有选择 `Approve and implement` 才恢复执行模式并继续实施。反馈与取消不会退出 Plan，也不会默认同意计划。

审批显示批准后采用的模式。通过 `enter_plan_mode` 或 `/plan` 进入时均记录进入前的 Yolo、Audited 或 Auto-audit；批准后自动恢复该模式并继续执行。取消或离开规划不会执行计划。批准计划不会绕过执行模式本身的工具审核。

## 状态与恢复

计划保存在当前会话状态目录的 `plan.json`，包含完整正文、审批状态、执行模式和修改意见。此文件属于会话数据，不会改写项目根目录的 `plan.md`。工具结果记录获批正文及记录路径，可在恢复会话后继续查看。

审批使用独立请求标识绑定本次计划快照；审批期间同批其他工具延后，需模型在获得回执后重新发起。计划模式继续禁止修改项目、安装依赖、修改外部状态和提交代码。

工具状态使用英文 `Planning`、`Reviewing plan`。TUI 与 Web 根据实际工具结果同步模式；历史事件重放不会覆盖用户当前选择。

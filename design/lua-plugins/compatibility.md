# API 版本、错误与维护规则

`api_version` 描述宿主接口协议，清单 `version` 描述插件自身版本。当前宿主只接受 `api_version = 1`，插件版本须符合 SemVer；两者不能互相替代。

## v1 兼容边界

- 新增可选接口、请求字段或独立能力时保留已有参数默认值。缺省授权保持关闭；有效能力仍为声明与用户授权的交集。
- 现有成功调用的参数或返回含义发生不兼容变化时，需要新的 API 版本或显式选择的新接口。不能在同一入口静默重新解释字段。
- 权限漏洞修复、非法输入拒绝、预算计费和依赖缺陷修复可以收紧原来不应保证的行为；发布说明必须列出影响、理由及验证范围。
- 文档标明弃用入口、替代方式、首次弃用的宿主版本和计划移除的 API 版本。弃用不自动删除 v1 入口；没有声明弃用的接口不因重构而更名。
- 插件清单、请求对象和注册协议按各自契约拒绝未知字段；不能把未知字段当作跨版本探测机制。返回值允许演进时，插件只消费文档字段，不依赖 JSON 字段顺序。

目前没有已宣布的 v1 弃用接口，也没有宿主版本范围、通用特性查询或自动 API 升级入口。`api_version = 1` 不代表所有历史 v1 程序都有最新新增能力。发布者应列出所需 API、真实验证的 `sai --version`、发布版本或构建标识；同一未发布版本号的不同构建需另外记录提交或程序摘要。

如果只是可选的纯 Lua 表函数，可以通过 `type(sai.time.utc_now) == "function"` 等方式选择替代路径；句柄方法只在取得有效句柄后检查。必需的能力缺失时明确报错，不静默执行权限更大的替代操作。旧构建遇到未知清单能力会在 `check/install` 阶段拒绝加载。

源码目录加载现在拒绝 Linux 文件或目录名称中的字面反斜杠。旧构建会将它改成 `/`，使 `modules\check.lua` 与 `modules/check.lua` 合并，丢失其中一份源码；这属于非法输入修复，不改变正常嵌套目录的语义。修正时先核对两个文件，再将需要保留的模块放入真实子目录。检查失败不会替换已有安装或修改配置；旧归档如果已经丢失源码，升级宿主不能恢复丢失内容，需要从原始目录重新打包。实际覆盖范围见[路径验收](distribution.md#复现命令行验收)。

## 参数、返回与错误

[能力清单](capability-matrix.md)按场景链接每类参数、返回值、权限、可调用阶段及资源限制。Lua 数组、JSON null、原始大整数和不可序列化的缓冲句柄需要分别处理，不能全部当作普通 Lua 表。

入门模板与独立示例可使用[LuaLS 类型提示](editor-support.md)。声明只覆盖列出的接口；静态检查不能替代宿主版本、授权、Schema 和资源校验。

| 错误类别 | 可观察行为 | 调用者处理 |
| --- | --- | --- |
| 清单、模块、语法、注册 | 整个包加载失败；`check/pack/install` 非零退出，发现入口报告诊断 | 修复对应文件、行号或契约；不留下部分注册 |
| 设置或业务参数 | `configure` 失败保留旧设置；工具 Schema 在业务执行前检查 | 设置校验由插件初始化实现，参数约束写入工具 Schema |
| 权限或调用阶段 | 宿主拒绝执行；事件不能批准宿主已拒绝的操作 | 核对 `info --json` 的有效授权、白名单、计划模式和当前阶段 |
| 网络及 I/O | Lua 可捕获错误；日志不应回显带密钥 URL 或业务秘密 | 提供可定位的上下文，只在明确幂等的操作中重试 |
| HTTP 错误状态 | 默认仍返回状态和有界正文，属于成功收到响应 | 显式检查 `status`；可以选择跳过错误正文 |
| 资源、期限与外部取消 | 请求或整个回调失败；迟到结果不交付 | 缩小单次工作量，核对额度；不要依赖取消补发结束事件 |

当前错误以 Lua/宿主异常和 CLI 非零退出表达，没有稳定的机器错误码。错误文本供人定位，不承诺逐字节不变；禁止依赖完整文案选择权限或数据提交分支。需要“未找到”“条件不匹配”等正常状态时，使用对应 API 已定义的 `nil/null/false` 或结构化字段。

`pcall` 可处理单次操作错误，但不能保证预算耗尽或整个回调取消后继续执行业务。超时也不保证已经开始的文件、进程、通知、调度或远端操作没有产生效果。数据变更应使用现有比较交换、条件发布或显式后续查询，并分别遵守接口的回收边界。

## 发布和更新

使用 `plugins pack` 生成源码归档；压缩包需先解压，再交给本地安装器。打包格式、SHA-256、替换更新与卸载见[分发文档](distribution.md)。发布说明至少包含插件 SemVer、所需 API、平台、外部程序/服务、能力用途、配置示例、数据格式和清理方式。README 与发布说明另行提供；图片、原生库等任意资源不会自动安装。

清单规范输出仍遵守 64 KiB 读取上限。格式化后超限时，打包和安装改用紧凑 JSON；补全默认字段后仍超限则失败。`check` 只读取和初始化，可能接受原始文件小于上限、但无法再次序列化保存的清单；发布前应实际执行 `pack`，并缩减超限声明。

安装器保留配置及显式授权，不按新清单自动扩权。来源、目录或进程模板变更后，应列出需要用户重新授予的具体项目。读取 `info --json` 可核对有效权限，但不会输出设置中的秘密值。

插件自己的数据格式应有版本标识及升级/回退规则。重新安装旧源码不等于数据回滚；卸载保留持久记录，需要清理的包应提供显式清理命令。远程目录、依赖求解和签名没有纳入当前安装协议，不作为使用本地扩展的前提。

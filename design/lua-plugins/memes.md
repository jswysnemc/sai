# 表情库插件

`plugins/memes` 提供六个原有工具和回复后自动发送策略。索引合并、查询评分、元数据、视觉提示词、删除恢复及发送规则全部由 Lua 实现。原 `src/tools/memes.rs`、`src/tools/memes/` 和专用 Rust 提示词已删除；`src/tools/vision.rs` 仍服务于文件读取，继续保留。

## 工具与模块

| 工具 | 访问类型 | 行为 |
| --- | --- | --- |
| `search_meme` | 只读 | 按关键词、标签和原评分规则查询，用户条目优先 |
| `show_meme` | 只读 | 显示当前启用图片，返回原元数据与动画说明 |
| `recent_meme` | 只读 | 查询默认库最近一次自动发送记录 |
| `add_meme` | 写入 | 读取本地图片，手工或通过独立视觉模型生成元数据，条件发布索引 |
| `update_meme` | 写入 | 更新字段、建立内置元数据覆盖、禁用或重新启用 |
| `delete_meme` | 写入 | 禁用内置图片，或将用户图片移入回收站／显式永久删除 |

六个公开名称、参数 Schema、双语说明和正常结果字段保持兼容。写入工具不进入计划模式目录。PNG、JPEG、WebP、GIF 沿用原扩展名规则；GIF 仍为静态终端预览，`animation_note` 的空值保留 JSON null。

```text
plugins/memes/
├── init.lua、sai-plugin.json       入口与能力声明
├── definitions.lua、descriptions.lua 工具契约与双语说明
├── tools.lua、values.lua           工具分发与原参数规则
├── settings.lua、paths.lua         设置校验与目录选择
├── index_schema.lua、index.lua     索引校验、完整读取与条件发布
├── library.lua、search.lua         用户覆盖、图片定位与排序
├── images.lua、display.lua         图片读取和终端显示
├── metadata.lua、prompts.lua       手工及视觉元数据
├── mutations/
│   ├── add.lua                    独占图片创建与索引新增
│   ├── update.lua                 字段更新与启停
│   └── delete.lua                 删除记录、文件操作与恢复
└── reply_state.lua、reply_decision.lua、reply.lua
                                  最近记录、模型判断与回复策略
```

## 配置与目录

可信内置包定向继承主配置 `plugins.memes`，`enabled` 仅决定未显式配置时的默认开关。`plugins.jsonc` 中的设置按字段覆盖旧值，不改写主配置。外部包不能继承这些目录、环境设置或默认授权。

| 设置 | 默认值或来源 |
| --- | --- |
| `libraries` | 旧映射；`default` 缺失时使用 `sai` |
| `width_percent` / `height_percent` | 35 / 25，保留 0–255 的原范围 |
| `max_image_mb` | 10，兼容旧 u64 整数范围；读取仍受宿主预算限制 |
| `allow_gif_animation` | false；当前渲染保持静态 |
| `auto_send_enabled` | 继承旧主配置；新建主配置默认 true，独立加载包默认 false |
| `auto_send_probability` | 0.2，按原 f32 精度计算 |
| `auto_send_min_confidence` | 0.8，按原 f32 精度计算 |
| `builtin_dirs` | 设置 `SAI_MEMES_DIR` 时只使用该目录，否则依次尝试 `src/memes`、`/usr/share/sai/memes` |
| `user_dir` | Sai 应用数据目录下的 `memes` |
| `state_dir` | Sai 应用状态目录下的 `memes` |
| `input_paths` | 当前调用工作目录 `.`；其他输入目录必须显式配置 |
| `language` | 当前界面语言，值为 `en` 或 `zh` |

直接独立加载包时采用 `.sai/memes`、`.sai/state/memes` 等清单默认目录。每个库使用 `<库目录>/index.json` 和 `images/`；最近发送记录沿用 `<state_dir>/<清洗后的默认库名>/auto-send.json`，JSON 根字段为 `last`。

```sh
cat > memes-settings.json <<'JSON'
{"auto_send_enabled":true,"auto_send_probability":0.2,"input_paths":[".","/home/example/Pictures"]}
JSON
sai plugins configure memes memes-settings.json
sai plugins enable memes --grant-declared
sai plugins enable memes --no-reply-policy
```

`configure` 用文件内容替换该插件的显式设置。`--grant-declared` 明确授予当前有效声明的全部能力。已有显式授权时，仅修改目录设置不会自动授予新路径；可用各目录授权选项更新对应类别。单独撤销回复策略仍可使用六个工具。

| 能力 | 用途 |
| --- | --- |
| `system.read_paths` | 输入图片、内置及用户索引、图片真实路径和旧发送记录 |
| `binary.write_paths` | 用户图片、用户索引和发送记录的条件写入 |
| `system.remove_paths` | 显式永久删除、竞争失败图片及替换后的旧图片清理，仅限用户库 |
| `system.trash_paths` | 用户图片移入系统回收站，仅限用户库 |
| `binary.display_images` | 终端尺寸与图片输出 |
| `vision` | 未提供手工元数据时使用独立视觉配置 |
| `model` | 自动发送候选判断，继承当前 Agent 文本模型 |
| `reply_policy` | 准备回复上下文和回复后的投递 |

授权取声明与用户授权的交集。读取或写入能力不会自动提供删除、回收站、模型或回复策略权限。普通文件写入和两类删除仍要求可信写入许可。终端展示能力本身允许宿主展示本地图片；本插件另行检查图片真实路径位于所属库 `images/` 内，拒绝指向库外的符号链接。这项检查不提供跨外部文件系统修改的原子快照保证。

## 索引与文件操作

每次索引读取取得完整字节和 SHA-256，不使用截断文本计算修订。索引最多 1 MiB、4096 个条目及 64 条待删除记录。拒绝损坏 JSON、非法 UTF-8、重复标识或图片路径、绝对路径、父目录跳转和不位于 `images/` 的文件名。更严格的路径与结构校验用于防止损坏或越界索引被静默覆盖。

用户条目覆盖内置同标识条目；仅修改内置元数据时保留原内置图片回退路径。禁用项可通过 `enabled=true` 恢复。当前同分候选保留原索引顺序，空结果仍为数组。原标识前缀、ASCII 标点及 Unicode 处理保持既有规则。

新增顺序为元数据校验、独占图片创建、索引条件更新。标识继续使用完整内容 SHA-256；新文件名为 `images/<摘要前16位>-<32位随机后缀>.<扩展名>`。独占创建避免删除重试误删随后重新添加的同内容图片。新名字不同于旧版固定摘要文件名，现有文件无需重命名。

索引条件冲突最多重试 16 次，每次重新读取并合并变更。不同图片的并发新增不丢失条目；相同图片竞争时仅一个结果进入索引，其他调用清理本次独占图片。禁用后重新添加会发布新元数据，并清理被替换的旧用户图片。

删除分三次操作：先条件发布 `pending_deletions`，再执行明确的回收或永久删除，最后条件移除原条目和记录。待删除项不参与搜索、显示、新增和更新。错误或取消保留记录，调用者通过 `delete_meme` 显式重试；未再次提供 `hard_delete` 时沿用记录中的方式，明确提供时才改变方式。记录绑定旧文件名和随机标记，完成步骤不能移除后来新增的同标识条目。

默认删除使用系统回收站。当前宿主仅验证 Linux 同文件系统的标准用户回收站；不支持的文件系统或平台明确报错，不会降级为永久删除。内置图片或使用内置图片的元数据覆盖只更新禁用记录。详细系统边界见 [单文件删除接口](file-removal-api.md)。

图片与索引之间没有多文件事务。图片创建后取消或进程退出可能留下未引用图片；重试新增不会自动回收它。索引发布后旧图片清理失败时，新增仍返回成功，并附带 `cleanup_error` 和 `unreferenced_path`。取消也可能发生在索引已提交但调用尚未返回之间，重试应先查询现状。插件不自动扫描删除未知图片。

条件写入和文件删除复用同一状态目录下的宿主文件锁；旧程序、其他状态目录、外部编辑器或自定义宿主不参与这套互斥。不要同时使用旧原生程序修改带有待删除记录的库。格式兼容不意味着旧程序理解新增恢复协议。

## 自动发送与上下文

通用 [回复策略接口](reply-policy-api.md) 在主请求前读取最近记录，按旧概率规则选择最多 12 个候选，再调用当前文本模型判断。用户消息按原规则截取前 1000 个 Unicode 字符；原中文判断提示词、候选字段、置信度及前缀选择规则保持一致。关闭自动发送、计划模式、空输入或无候选时不调用决策模型。

主模型收到当前轮计划提醒，文字回复完成后才显示图片。完成阶段重新读取当前库，拒绝准备后禁用、待删除或删除的条目。显示成功后才条件保存最近记录；下一轮通过 `plugin_reply_memes` 上下文资源恢复发送事实。显示失败不会伪造记录，也不改变已完成的主回复。

图片展示与状态写入同样不构成事务：展示后取消或记录保存失败，可能已经出现图片但没有新的持久记录。宿主不会自动重发这张图片。自动发送记录沿用准备时的业务事件时间。

Web 上下文预览通过实际 Lua 读取旧记录，不调用决策模型、不安排发送；终端同步用量视图使用已载入正文。`last_auto_meme` 原生资源在后续投影中清空。禁用或撤销回复策略后不再提供这份插件上下文。

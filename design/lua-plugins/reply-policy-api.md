# 回复策略接口

`sai.register_reply_policy` 允许插件在主模型请求前提供上下文和本轮提醒，在主回复完成后执行一次附属动作，并可通过 `after_tool` 在工具循环中提供提醒。候选选择、业务提示词和持久记录属于 Lua；Rust 负责实例归属、权限、预算、上下文投影及取消。实际消费者见[表情库](memes.md)和[会话待办](todo.md)。

## 声明与授权

```json
{"capabilities":{"reply_policy":true}}
```

```sh
sai plugins enable my-plugin --allow-reply-policy
sai plugins enable my-plugin --no-reply-policy
```

`reply_policy` 是独立布尔能力，必须同时满足清单声明与用户授权。它不继承 `notifications`、`system.notify`、`model` 或图片展示能力，也不授予这些能力。分项更新保留其他有效授权；两个选项互斥，并且不能与 `--grant-declared` 同时使用。未声明的能力不能授权，失败不改写配置。

外部包默认没有授权。可信内置包未保存显式授权时采用有效声明；已保存的显式授权不会因新能力或目录设置变化而扩大。启停、授权或源码变更需要当前 Agent 重载后生效；新建 Agent 使用新配置。

## 注册与返回值

```lua
--- 【回复示例】【准备上下文】提供当前实例的业务说明
--- @param input string 当前用户消息；预览时为空
--- @param ctx table 可信调用上下文
--- @return table 本插件上下文，不安排外部动作
local function prepare(input, ctx)
    return {context="当前会话已启用示例策略。"}
end

--- 【回复示例】【动作完成】完成回调没有需要保留的业务记录
--- @param delivery table 准备阶段返回的 JSON 对象
--- @param ctx table 当前可信调用上下文
--- @return nil 清除本插件上下文
local function complete(delivery, ctx)
    return nil
end

sai.register_reply_policy({prepare=prepare, complete=complete})
```

每个包最多注册一组策略，`prepare` 和 `complete` 都必须存在，可选增加 `after_tool` 函数。注册只允许发生在加载期；拒绝重复注册、错误类型和未知字段。工具表跨 Agent 复制时，策略及可选工具后回调是否注册都参与确定性检查。无工具的包同样可以注册策略。

| 阶段 | 输入 | 返回值 |
| --- | --- | --- |
| `prepare(input, ctx)` | 当前用户消息与上下文 | `nil` 或 `{context?, reminder?, delivery?}` |
| `complete(delivery, ctx)` | 原准备结果中的 JSON 对象与当前上下文 | `nil` 或 `{context?}` |
| `after_tool(input, state, ctx)` | 工具事实、当前循环状态与上下文 | `nil` 或 `{state?, reminder?}` |

`context` 是本插件的可选持久上下文快照；`reminder` 只针对当前轮。两者分别最多 16 KiB，拒绝换行、回车、制表符以外的控制字符，以及 `<context-resource`、`</context-resource` 宿主标记。空值表示没有对应文字。字段必须是字符串或 null，返回对象不接受未知字段。

`delivery` 必须是 JSON 对象，编码后最多 16 KiB；数组、字符串和其他值均拒绝。宿主保存该对象，只有完成阶段才交回所属实例。它不是后台任务，不落盘，不在重启后恢复，也不自动重试。`complete` 不接收主模型正文，不能改写已经完成的回复。

## 工具后回调

`after_tool` 使用同一项独立 `reply_policy` 声明和授权，不需要准备阶段返回投递计划。宿主传入以下 `input` 对象，不提供工具输出正文：

| 字段 | 含义 |
| --- | --- |
| `name` | 实际执行的公开工具名称 |
| `local_name` | 该工具属于本插件时的本地名称，否则为 null |
| `arguments` | 原工具参数解析成的 JSON；无法解析时为 null |
| `ok` | 实际工具是否成功；执行失败或 `tool error:` 前缀均为 false |
| `tools` | 当前注册表仍提供的本插件本地工具名称数组 |

工具过滤会反映在 `tools` 中，插件应据此判断是否还能要求模型执行某个工具。`todo` 在目录没有 `todo` 时返回 nil，因此计划模式、白名单过滤及网关目录不会产生要求使用不可见待办工具的提醒。

`state` 初始为 JSON null，后续传入该策略上次成功返回的状态。返回状态必须为最多 16 KiB 的 JSON 对象或 null；省略、null 或整个返回 nil 会清除状态。返回对象拒绝未知字段；`reminder` 沿用 16 KiB 文本、控制字符和宿主资源标记限制。合法提醒作为 system 消息追加到当前工具循环，不替换工具结果，也不更新 `plugin_reply_<id>` 上下文快照。

宿主把状态绑定到插件实例、会话、存储会话、用户操作和工作目录，归属变化或实例失效时清除。每个工具循环重新从空状态开始，不落盘、不跨轮复用；Lua 全局变量不替代这份宿主状态。回调错误不会提交部分返回值，同一有效实例保留此前状态，主回复和原工具结果继续处理。

该回调按事件权限执行：`ctx.allow_writes=false`，不提供模型或工具调用服务，禁止修改会话存储、插件存储或创建私有工作目录。其他宿主接口继续执行自身授权和只读约束，修改 Lua 字段无法扩大权限。每次分发最多处理八个策略，共享 60 秒总期限，另受包自身预算限制。

当前接入 Sai 内核普通串行工具完成分支，与原待办提醒位置一致。并发只读工具组、宿主门禁提前拒绝及特殊分支不触发此回调，直接工具或插件命令入口也不单独启动 Agent 工具后策略；它不承诺覆盖所有 `tool_result` 事件。回调失败和超时只记录诊断，外部取消不补发提醒。

## 阶段与权限

准备时 `ctx.allow_writes` 固定为 false，`ctx.reply_can_deliver` 表示宿主是否允许后续完成阶段。修改这两个 Lua 字段不能改变 Rust 权限。后续投递被禁止时，准备结果中的非空 `delivery` 会报错。

准备期沿用现有只读工具语义：需要可信写入许可的普通文件修改、跨会话存储、通知和调度操作会拒绝；已授权的会话私有缓存及终端展示仍遵守各接口原有规则。插件应把需要在主回复后发生的动作放进 `complete`。`memes` 的准备函数只读取状态、索引及调用决策模型，不绘图、不写入文件。

当前 Agent 的文本模型和工具目录按独立能力交给策略。准备期只提供只读工具，仍执行名称白名单和调用链限制；模型返回的工具建议不会自动执行。空输入且禁止投递的上下文预览不绑定模型或工具服务。网络、文件、二进制缓冲等接口继续受自身授权和预算限制。

`PreparedReply` 在 Rust 中不可克隆，绑定插件实例、会话、存储会话、用户操作、工作目录和原后续写入许可。准备需要非空会话、操作和工作目录。完成时消费该结果，拒绝实例替换、归属变化或从只读准备升级为写入；调用失败也不能复用结果。

应用在完成前重新核对当前策略实例、实时计划模式和取消标志。主回复先写入 completed 终态，再发出外部输出事件并执行附属动作。策略错误只记录诊断，不能把已经完成的主回复改成失败。主回复失败或取消时，未消费计划不会投递。

## 上下文投影

宿主使用固定资源名 `plugin_reply_<插件 ID>`，插件不能选择核心资源名称。准备后的上下文绑定产生它的实例；禁用、撤权或替换实例后不再沿用旧快照。资源更新清除失效插件和旧原生 `last_auto_meme` 资源，并在内容变化或压缩移除正文时重新提供完整内容。

准备阶段提供的本轮提醒贯穿初次模型请求、工具循环、压缩重建和上下文溢出恢复。它不复用到下一轮。`after_tool` 提醒在对应工具完成后才追加，循环状态单独管理。完成返回的上下文更新 Agent 快照；下一轮再次执行准备，以业务持久状态为准。插件需要自行保存可恢复记录，Lua 全局变量不保证跨会话或重启保留。

Web 上下文预览通过独立实例，以空输入、禁止投递和无模型服务调用准备函数。终端流式用量视图保持同步，从已载入历史资源恢复正文，按当前启用策略过滤，不等待异步回调。两种视图可能分别展示最新持久记录和当前已经载入的正文。

此接口接入 Sai 自带对话内核。外部内核仍保持已有 Agent 生命周期事件，不额外执行无法与其主回复提交顺序绑定的回复策略。通知纯回调 `reply_end` 继续由各交互面独立计算。

## 预算与取消

| 项目 | 上限 |
| --- | --- |
| 当前用户输入 | 64 KiB，并受更小的 `limits.output_bytes` 限制 |
| 每个 context / reminder | 各 16 KiB |
| delivery JSON | 16 KiB |
| 工具后回调 input JSON | 64 KiB，并受更小的 `limits.output_bytes` 限制 |
| 工具后回调 state JSON | 16 KiB，对象或 null |
| 应用每阶段处理策略数 | 8，按插件目录顺序 |
| 应用单阶段总等待 | 60 秒 |

每阶段调用继续遵守包自身的指令、堆内存、输出、模型次数及 I/O 时限。总阶段期限可以比包时限更早结束。错误结果不会进入上下文，准备超时不会阻止主回复。

外部取消会回收本次 Future、服务租约和调用句柄，后续有效调用仍可使用 VM。已经完成的外部操作不会随取消回滚；完成回调必须按各宿主接口约束处理部分完成，不能依赖取消后再次进入 Lua 清理代码。

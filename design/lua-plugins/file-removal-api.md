# 单文件删除与回收站接口

`sai.fs.remove_file(path)` 永久删除单个普通文件，`sai.fs.trash_file(path)` 将单个普通文件移入系统回收站。两者使用独立目录授权，并要求可信调用上下文允许写入。目录、符号链接、FIFO、套接字和设备均拒绝；接口不提供递归删除。

## 权限与调用

| 接口 | 独立能力 | 成功结果 |
| --- | --- | --- |
| `sai.fs.trash_file(path)` | `system.trash_paths` | 文件已移入回收站为 `true`，授权目标缺失为 `false` |
| `sai.fs.remove_file(path)` | `system.remove_paths` | 文件名称已解除链接为 `true`，授权目标缺失为 `false` |

```json
{
  "capabilities": {
    "system": {
      "trash_paths": ["output/images"],
      "remove_paths": ["output/images"]
    }
  }
}
```

两类目录各自最多 64 项，缺省为空。清单与用户授权按字段及完整路径字符串取交集，修改目录声明不能沿用旧授权。`system.read_paths`、`binary.write_paths`、工具授权和两类删除能力相互独立；删除不需要读取正文的权限，也不会授予正文读取或任意文件写入能力。

```sh
sai plugins enable image-library --allow-trash-path output/images
sai plugins enable image-library --allow-remove-path output/images
sai plugins enable image-library --no-file-trash
sai plugins enable image-library --no-file-remove
```

同类 `--allow-*` 可重复指定，替换该类授权集合；未指定类别保持原有效授权。分项选项不能与 `--grant-declared` 混用，未声明的目录和冲突参数不会写入配置。授权变更在后续加载生效，已有实例继续使用加载时的授权快照。

接口仅在工具或命令回调中开放。回调必须拥有真实写入权限；只读工具、计划模式和所有事件都不能删除文件。Lua 修改 `ctx.workdir`、`ctx.allow_writes` 不会影响 Rust 保存的目录和权限。没有实现 `PluginHost::remove_file` 的宿主明确返回不可用，不调用旧工具代替。

```lua
local trashed = sai.fs.trash_file("output/images/old.png")
return {trashed=trashed}
```

业务只有明确选择永久删除时才调用 `remove_file`。回收失败不会自动改为永久删除。

## 路径与结果

每个接口严格接受一个 UTF-8 字符串参数，最多 4096 字节；复制路径前检查大小。缺失参数、多余参数、数字、布尔值、表和非法 UTF-8 均报错。路径支持绝对路径、相对于可信工作目录的路径和 `~/…`，禁止父目录跳转、通配符、控制字符、Windows 设备名、数据流名称及尾部点或空格等规范化歧义。

声明表示目录，目标必须严格位于其中；不能删除授权根本身，单个文件声明也不能用作该文件的删除授权。宿主先规范化父目录、检查完整范围，再逐级打开不跟随替换链接的目录句柄。末级名称保持原样，初始符号链接即使指向授权目录内部也拒绝。

缺失文件和缺失父目录都在完整授权之后返回 `false`，不创建目标父目录。权限、类型、平台或文件系统错误均返回错误，不伪装成缺失。准备与提交之间的文件标识变化会报错；Unix 比较设备与 inode，Windows 比较卷与文件标识，无法取得标识时拒绝。

永久删除只解除单个目录项，不覆盖文件内容，不执行安全擦除。已有的其他硬链接和打开句柄仍遵循操作系统规则。

## Linux 回收站

正式宿主当前支持 Linux 标准用户回收站 `$XDG_DATA_HOME/Trash`；数据目录缺省遵循 `$HOME/.local/share`。数据目录来自可信宿主环境，Lua 不能指定回收站位置。实现遵循 [Freedesktop Trash Specification 1.0](https://specifications.freedesktop.org/trash/1.0/) 的目录和信息文件格式。

回收站及其 `files`、`info` 子目录必须属于当前用户，权限为 `0700`，并且不能是符号链接。缺失目录通过固定父目录句柄创建；已有目录不满足条件时直接报错，不修改其权限。已经位于该回收站内部的文件不能再次回收。

每个条目先以独占创建方式预留 `info/<name>.trashinfo`，使用 `0600` 权限写入并同步：

```ini
[Trash Info]
Path=/absolute/original/image%20name.png
DeletionDate=2026-09-11T12:30:00
```

`Path` 保存规范父目录和原始文件名，按文件系统字节进行 URL 百分号编码；`DeletionDate` 使用本地时间。存储名称包含有界原名片段和随机后缀，重复回收同名文件不会覆盖旧条目。原名与还原位置以 `Path` 为准，不从存储名称推断。

源文件和回收站必须支持同一文件系统内的 `renameat2(RENAME_NOREPLACE)`。移动相对已打开的目录句柄执行，目标占用时原子拒绝覆盖。跨设备、内核或文件系统不支持该操作时明确失败；不复制后删除，也不使用应用私有备份代替系统回收站。原文件字节、权限、修改时间和扩展属性随同一 inode 保留。

提交前后复核标准目录位置、信息文件身份及实际移动对象。若移动期间发生变化，优先使用禁止覆盖的重命名还原；原名已被占用时保留捕获对象和还原信息并报错，不覆盖竞争方文件，也不递归处理捕获到的目录。

Windows、macOS 和其他平台尚未提供该回收站适配，对存在文件返回不可用。授权目标已经缺失时仍返回 `false`。本轮实际验证来自 Linux，包括使用现有 `trash` 库还原指定测试条目；测试不枚举用户回收站。

## 互斥、预算与取消

正式 `PrivatePluginHost` 将两类删除与二进制普通、条件写入绑定到同一个状态锁。文件名继续使用 `state_dir/plugin-binary-write.lock`，实现位于 `src/plugins/file_ops/lock.rs`。锁覆盖目标检查、回收站信息准备、提交与清理；删除接口按路径和文件标识保护锁本身及其别名。

互斥范围是使用同一应用状态目录的新版正式宿主。外部编辑器、原生业务的其他文件操作、旧程序、其他状态目录、自定义宿主或模板进程不参与。目录句柄限制操作范围，但上述外部修改不属于完整事务保证；提交复核与恢复不能代替跨进程文件系统事务。

每次进入宿主消耗一个 `system_calls` 额度，成功、缺失和宿主错误均计数。运行时拒绝的参数及缺失授权不消耗额度。接口不读取正文或创建二进制缓冲，不使用二进制字节预算。

锁等待和整个调用受 `limits.timeout_ms` 约束；直接宿主调用的锁等待另有十分钟硬上限。阻塞工作线程只准备目标句柄、锁和还原信息，成功等待后才执行删除或移动。排队取消不启动准备；迟到的准备结果只尽力清理本次信息文件，继续持锁直到清理完成，不开始源文件变更。

已经开始的文件系统调用不能保证立即中断，完成的永久删除或回收移动也不能因随后发生的超时而撤销。因此调用报错或超时不普遍等价于源文件未变化。取消或错误可能保留空回收目录、固定锁文件；清理失败可能保留未配对的信息文件。进程崩溃和断电不具有跨目录事务恢复保证。

这些接口只提供宿主文件能力；表情库索引业务、六个工具和自动发送策略仍待整体迁入 Lua。
